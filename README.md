# 分钟K线图特征提取与重建（AE / CAE）

## 一、项目目标

对分钟K线图图片进行**特征提取**，得到一个低维特征向量（latent vector），再用该特征**重建原图**。
如果重建图与原图足够相似，就说明该特征向量已经充分编码了原图的信息——即"特征提取是充分的"。

因此本项目以**原图与重建图的相似度**作为损失函数（相似度越高、损失越低），采用 **自编码器（AE）** 或 **卷积自编码器（CAE）** 实现。

```
原图 x ──► 编码器 Encoder ──► 特征向量 z（低维） ──► 解码器 Decoder ──► 重建图 x̂
                                                    │
                            损失 L = 相似度损失(x, x̂)（越小说明 z 越充分）
```

## 二、数据说明

本地样例数据位于 [分钟k线图/](分钟k线图/) 文件夹，共 **36 张 PNG**，命名格式为 `股票代码_日期.png`（如 `300001_2019-01-03.png`），内容为单日分钟级K线图：上半部分为价格走势，下半部分为成交量柱。

**完整数据集在远程机器上：`E:\k_graphy\分钟k线图`，共 2,076,107 张（约 207 万）同格式图片**——样本量完全不是瓶颈，本地 36 张仅用于格式确认与流程调试。

### 图片格式检查结论（已实测）

| 项目 | 实际值 | 说明 |
|------|--------|------|
| 尺寸 | **448 × 448**（宽 × 高） | **不是 224×224**，是其 2 倍 |
| 通道 | **4 通道 RGBA** | numpy shape 为 `(448, 448, 4)`，dtype `uint8` |
| Alpha 通道 | 恒为 255（全不透明） | **不携带任何信息，可直接丢弃** |
| RGB 通道 | **彩色**：白底 (255,255,255)，红 (214,39,40) 与绿 (44,160,44) 的K线/成交量柱（红涨绿跌），另有抗锯齿过渡色；彩色像素约占 5%~9% | **颜色编码了涨跌方向，属于关键信息，必须保留 RGB 三通道，不能转灰度** |
| 一致性 | 36 张图片尺寸、模式全部一致 | 无需处理异常样本 |

> 关于 Alpha：RGBA 中的 A（Alpha）是**透明度通道**，0 表示完全透明、255 表示完全不透明。本数据中所有像素的 Alpha 均为 255（整张图完全不透明），一个恒定不变的通道没有任何信息量，因此预处理时直接丢弃，把 4 通道降为 RGB 3 通道。

> 结论：原始数据为 **448×448×4**，而非 224×224×深度。若模型需要 224×224 输入，需在预处理中缩放。

## 三、预处理方案

1. **丢弃 Alpha 通道**：恒为 255，无信息量，4 通道 → 3 通道。
2. **保留 RGB 三通道**：红/绿颜色编码了涨跌方向，是关键信息，**不做灰度化**。
3. **尺寸**：**保持 448×448 原尺寸训练**（数据本身即此格式，且K线线条较细，下采样可能模糊细线）。仅当后续引入 ViT 等要求 224×224 输入的模型时，再做 2 倍整数下采样（`INTER_AREA` 失真最小），或对 ViT 位置编码做插值以支持 448 输入。
4. **归一化**：像素值除以 255 归一到 `[0, 1]`；由于图片是白底（大部分像素为 255），也可考虑**反色**（`1 - x`，逐通道），让线条为高激活值、背景为 0，通常更利于卷积网络学习稀疏线条特征。
5. **数据划分**：本地 36 张样本全部用于训练跑通流程（已完成）；迁移到远程约 207 万张正式训练时，按 **7:2:1 划分训练/验证/测试集**——训练集拟合模型，验证集调超参与早停，测试集只在最终验收时用一次。

## 四、模型方案

> **"基线（baseline）"与"主方案"的含义**：基线是一个刻意选的简单参照模型，作用是提供一个成绩下限——主方案的效果必须明显超过基线，才能证明其复杂度是值得的；主方案则是预期效果最好、真正要用的模型。基线不是必须实现的，只是实验对照。

### 方案 A：全连接自编码器（AE）——基线（可选）

- 输入拉平为一维向量后经全连接层压缩、再对称展开重建，输出层用 `Sigmoid` 保证像素在 `[0,1]`。
- 注意：448×448×3 拉平后约 60 万维，第一层全连接参数量会爆炸，**若做此基线需先降采样到较小尺寸（如 112×112）**，仅作对照参考。
- 缺点：不利用图像局部结构，对线条类图像重建效果通常一般。

### 方案 B：卷积自编码器（CAE）——主方案

- **编码器**：若干层 `Conv2d + BatchNorm + ReLU`，用 stride=2 逐步下采样
  （例：`3×448×448 → 32×224×224 → 64×112×112 → 128×56×56 → 256×28×28 → 512×14×14`），
  最后接全连接层压缩为特征向量 `z`（维度 128~512 可调）；
- **解码器**：全连接层恢复空间尺寸后，用 `ConvTranspose2d`（或 `Upsample + Conv`，可减少棋盘伪影）逐步上采样，对称还原到 `3×448×448`，输出层 `Sigmoid`；
- **特征向量 z 即为本项目要提取的图片特征**，训练完成后单独取编码器做特征提取器。

### 方案 C：ViT 编码器 + 解码器（MAE 风格）——进阶方案

**ViT 与 AE/CAE 并不冲突，而是两个不同层面的概念**：

- AE/CAE 说的是**训练框架**：编码 → 低维特征 → 解码重建，以重建相似度为损失；
- ViT / CNN / 全连接说的是**编码器用什么骨干网络**。框架里的编码器换成 ViT，就得到 "ViT 自编码器"——业界著名的 **MAE（Masked Autoencoder, He et al. 2022）** 正是这种组合：ViT 做编码器 + 轻量解码器做像素重建。

因此三个方案的关系是：同一个"编码-重建"框架下，编码器分别为 全连接（A）、CNN（B）、ViT（C），可以逐个实验、横向对比特征质量。

ViT 方案的注意事项：

1. **数据量**：ViT 从零训练非常吃数据，36 张图远远不够。应加载 **ImageNet 预训练权重**（如 `timm` 的 ViT-B/16），冻结或小学习率微调编码器，重点训练解码器。
2. **输入尺寸**：标准 ViT-B/16 输入为 224×224×3（切成 14×14=196 个 patch）。本项目数据为 448×448，两种处理方式：
   - 下采样到 224×224 喂给 ViT（448 恰为 2 倍，失真小）；
   - 对位置编码做双三次插值，让 ViT 直接吃 448×448（patch 数变为 28×28=784，计算量约 4 倍）。
3. **特征取法**：取 `[CLS]` token 或对全部 patch token 做池化，作为图片特征向量 z。

### 特征维度选择

从大到小尝试（如 512 → 256 → 128 → 64），观察重建质量拐点：能保持重建相似度达标的**最小维度**，就是"充分且紧凑"的特征表示。

## 五、损失函数（图片相似度度量）

以原图 `x` 与重建图 `x̂` 的相似度作为损失，可选/可组合：

| 损失 | 公式/工具 | 特点 |
|------|-----------|------|
| MSE（均方误差） | `mean((x - x̂)²)` | 最常用基线，逐像素比较，易训练但重建偏模糊 |
| BCE（二值交叉熵） | `binary_cross_entropy(x̂, x)` | 逐通道逐像素比较，适合归一化到 [0,1]、大面积纯色背景的图像 |
| **SSIM 损失（推荐）** | `1 - SSIM(x, x̂)`（可用 `pytorch-msssim`） | 结构相似性，直接对应"两张图相似度"的目标，对线条结构敏感 |
| 组合损失 | `L = α·MSE + (1-α)·(1-SSIM)`，α≈0.5 | 兼顾像素精度与结构相似度，实践中常优于单一损失 |

**实测结论（2026-08-12，36张样例上的对照实验，详见 开发计划.md 阶段4记录）**：

1. **训练损失默认用纯 MSE（alpha=1.0）**。SSIM 项在训练早期会把梯度引向"输出全白背景"的退化解（白色占 91% 像素时 SSIM 对纯白输出已给出 0.834 的高分），拖慢甚至阻碍K线结构的学习；纯 MSE 反而能快速学出结构和红绿颜色。
2. **SSIM 作为评估指标需要校准后解读**：此类细线条图上，原图仅横移 1 像素 SSIM 就掉到 0.869，视觉上几乎完美的重建也只得约 0.87——**SSIM ≥ 0.95 在此图像域不可达**，不能作为达标线。
3. **重建达标线改为**：平均 PSNR ≥ 30dB（对应 MSE ≤ 0.001）+ SSIM ≥ 0.86（约等于"1像素错位"水平）+ 肉眼确认K线形态与红绿颜色还原。

## 六、训练与评估

### 样本量规划

| 用途 | 预估所需样本量 | 说明 |
|------|--------------|------|
| 跑通流程、验证网络能过拟合 | 本地 36 张即可 | — |
| CAE 从零训练可用特征提取器 | 约 5,000 ~ 20,000 张 | 从远程 207 万张中随机抽样即可 |
| ViT（ImageNet预训练）微调 | 1万张以上 | 同上 |
| ViT 从零训练 | 10万张级别 | 数据量够，但训练成本高，非首选 |

> 依据：本数据图像域很窄（固定布局、白底、固定配色），有效变化只在K线形态，所需样本比自然图像少约一个量级。远程机器 `E:\k_graphy\分钟k线图` 已有 **2,076,107 张（约 207 万）**，样本量不是瓶颈。**建议初期从中随机抽样 5,000~20,000 张快速迭代**（注意覆盖不同股票与涨/跌/震荡阶段），方案定型后再考虑放大到全量。

### 分阶段训练策略

1. **第一阶段（当前）**：直接用 **448×448 原尺寸**训练 CAE，评估重建效果——数据本身就是这个格式，零预处理成本。
2. **关于降采样的工程决策**：207 万张若逐张离线降采样再存盘，工作量与存储开销都很大，**且完全没有必要**——如果后续实验需要 224×224（如 ViT 方案），在 `Dataset`/`DataLoader` 的 transform 中**在线 resize**（`torchvision.transforms.Resize`），加载每个 batch 时随读随缩放即可，不生成任何磁盘副本，GPU 训练时 CPU 并行做 resize 几乎不增加耗时。
3. **降采样画质实测结论**（见 `降采样对比_224/`）：原图每根分钟K线仅约 1.9 像素宽，降到 224×224 后单根K线细节必然受损——AREA 均值插值保形态但相邻红绿K线混色，NEAREST 保颜色但会整根丢K线。这也是第一阶段坚持 448 原尺寸的原因；224 仅在 ViT 方案下作为妥协选项。

### 训练配置

- **框架**：PyTorch
- **优化器**：Adam，学习率 `1e-3`（配合 `ReduceLROnPlateau` 衰减）
- **Batch size**：8~16（样本少，不宜过大）
- **Epochs**：200~500，观察损失收敛
- **评估指标**：
  1. SSIM（主指标，结构相似度）
  2. PSNR（峰值信噪比）
  3. 肉眼对比图：原图 vs 重建图并排可视化（重点看K线线条、成交量柱是否清晰还原）
- **实验记录**：不同特征维度 d 下的 SSIM/PSNR 对照表，确定最小充分维度。

## 八、代码规范（注释规则）

本项目代码必须遵守以下注释规范：

1. **模块化组织**：数据加载、模型定义、损失函数、训练、评估分文件编写（见第七节目录结构），每个文件职责单一。
2. **模块级注释**：每个 `.py` 文件开头用文档字符串说明本模块的功能、在整个流程中的位置。
3. **函数/类注释**：每个函数和类写 docstring，说明功能、参数（含类型和含义）、返回值；神经网络相关代码必须**标注张量 shape 的变化**，例如：
   ```python
   def forward(self, x):
       """编码器前向传播
       参数:
           x: 输入图片张量, shape (B, 3, 448, 448), 取值范围 [0, 1]
       返回:
           z: 特征向量, shape (B, latent_dim)
       """
   ```
4. **复杂用法必须注释并解释语法**：凡是用到不直观的写法——如张量维度变换（`view/permute/einsum`）、切片技巧、生成器表达式、装饰器、上下文管理器、lambda 等——须在行内或行上注释说明**这行在做什么、该语法如何理解**，例如：
   ```python
   # permute 交换维度顺序: (B, H, W, C) -> (B, C, H, W)，PyTorch 卷积要求通道在前
   x = x.permute(0, 3, 1, 2)
   ```
5. **关键超参数注明含义与取值理由**（如 latent_dim、学习率、损失权重 α）。
